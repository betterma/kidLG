# KidLG 开发说明书 · 世界级阶段 / 激活码 / MVP 地图

> **当前开发设定（已修订）：** 站点与配置走 **GitHub Pages + 仓库 JSON**；进度 **未激活仅本机，已激活本机 + 静默同步到 GitHub**；腾讯云支付/硬校验 **延后**。

---

## 0. 托管与数据（现行）

| 内容 | 存放 | 说明 |
|------|------|------|
| 游戏网页 | GitHub Pages | 推送后访问 |
| 世界阶段、价格、关卡表 | `data/stages.json`、`data/levels/` | 前端 `fetch` |
| 激活码表（演示用） | `data/codes.json` | 软门禁；公开仓可见 |
| 音效、图片 | `assets/` | Pages 静态 |
| 进度（未激活） | 仅 `localStorage` | |
| 进度（已激活） | `localStorage` + GitHub `data/progress/` | 本机为主，后台静默备份 |
| 腾讯云 | 延后 | 支付发码、硬校验等 |

### 推荐仓库结构

```
KidLG/
  docs/
  data/
    stages.json
    codes.json
    levels/letters/…
    progress/              ← 已激活用户的云端进度（按码哈希命名）
      <codeHash>.json
  assets/
  web/
  sync/                    ← 可选：写 GitHub 的中转（Worker 等），Token 不进前端
  README.md
```

### 进度策略（定案）

```
未激活：  只写 localStorage
已激活：  先写 localStorage → 后台静默 PUT 到 GitHub（失败不影响玩）
换设备：  输同一激活码 → 拉取 GitHub 进度 → 与本机合并 → 再写回两边
```

**合并规则：** 同关取更好成绩；解锁取并集；尝试次数累加；`updatedAt` 取最新。

**为何不能「网页直接 commit 到 GitHub」：**  
写入仓库需要 Token。Token 若写进前端 JS，任何人都能打开开发者工具偷走并篡改你的仓库。  
因此「偷偷同步给 GitHub」的正确做法是：

1. 前端只调用你的 **同步中转**（例如免费 Cloudflare Worker：`POST /progress`）  
2. 中转持有 **仅能写 `data/progress/*` 的 fine-grained PAT**  
3. 中转再调用 GitHub Contents API 更新 `data/progress/<codeHash>.json`  

MVP 可分两步：① 先做本机进度 + 激活后调用同步接口的代码路径；② 再补上免费 Worker。没有中转前，激活态也先只落本机，但数据结构按「可同步」设计。

**隐私：** 文件名用激活码的哈希（如 SHA-256 前 16 位），不要用明文码；公开仓仍可能被扫到进度内容，重要数据建议私有仓或以后迁库。

### Owner / 零售

| `APP_EDITION` | 行为 |
|---------------|------|
| `owner` | 全开；可不输码。进度默认可仅本机；若你配置了同步中转，也可用「调试同步码」测上传 |
| `retail` | 读 `stages.json`；收费世界靠本机权益；**仅激活后**才启用 GitHub 静默同步 |

改价 = 改 `stages.json` 后 push。

### 本阶段仍不做的

- 支付成功自动发码  
- 激活码服务端硬作废（公开 `codes.json` 可被下载）  
- 把写仓 Token 塞进前端  

产品模型保留；进度按「未激活本机 / 激活本机+GitHub」实现。

## 3. 阶段与定价（`data/stages.json`）

```ts
type StageConfig = {
  stageId: string;          // 如 world.letters
  name: string;
  sortOrder: number;
  listed: boolean;
  access: "free" | "paid";
  priceYuan: number | null;
  validity:
    | { type: "lifetime" }
    | { type: "days_from_activate"; days: number }
    | { type: "fixed_date"; until: string };
  levelGroupIds: string[];
  payProductHint?: string;  // 预留；本期不用
};
```

### 门禁规则（零售）

| 条件 | 结果 |
|------|------|
| `access === "free"` | 任意设备可玩 |
| `access === "paid"` | 本机曾成功兑换且未过期、且 entitlements 含该 `stageId` |
| Owner | 跳过检查 |

## 4. 激活码（`data/codes.json` · 演示）

```ts
type ActivationCode = {
  code: string;
  stages: string[];
  status: "unused" | "active" | "expired" | "revoked";
  validity: StageConfig["validity"];
  activatedAt: string | null;   // 静态表可先恒为 null，兑换结果写 localStorage
  expireAt: string | null;
  deviceIds: string[];          // 静态表可先 []；绑定记录只写本机
  createdAt: string;
  note?: string;
};
```

### 本阶段兑换怎么做

1. 前端加载 `codes.json`，查找匹配 `code`  
2. 校验 `status`、按 `validity` 算是否过期  
3. 通过则把 `Entitlements` 写入 **localStorage**（本机生效）  
4. `deviceIds` / 服务端作废：**不做真校验**（静态站无法安全改 GitHub）

正式零售前：改为云函数读库校验；GitHub 只托管前端。

### 一码多世界（模型保留）

- 生成时 `stages` 可多选  
- 「补开」在现行阶段 = 你改 `codes.json` 里该码的 `stages` 后重新部署

## 5. 进度、报告与权益

### 5.1 存什么（现行）

| 存什么 | 未激活 | 已激活 |
|--------|--------|--------|
| 关卡进度、星 | 仅 `localStorage` | `localStorage` + 静默同步到 `data/progress/<codeHash>.json` |
| 学习事件 | 可选本机 | 可随进度快照一并同步（可二期） |
| 权益 | 无 | `localStorage`（兑换结果） |
| 阶段定价 | `stages.json` | 同左 |

### 5.2 进度快照形状（本机与 GitHub 共用）

```ts
type ProgressSnapshot = {
  codeHash: string;          // 激活码哈希；未激活可无此文件
  deviceId: string;
  updatedAt: string;         // ISO
  levels: Record<string, { stars: number; cleared: boolean; attempts: number }>;
  // 可扩展：今日目标、收集物等
};
```

### 5.3 静默同步时机（已激活）

- 通关 / 更新星级后（防抖，如 2–5 秒合并一次）  
- 退出关卡、切到后台（`visibilitychange`）时再试一次  
- 同步失败：只打日志，不弹窗；下次再试  
- 拉取：兑换成功或设置页「恢复进度」时 `GET` 中转 → 合并 → 写本机  

### 5.4 权益（Entitlements）

```ts
type Entitlements = {
  code: string;
  stages: string[];
  expireAt: string | null;
  deviceId: string;
  status: "active" | "expired" | "revoked";
};
```

`EntitlementGate` 读本机权益；Owner 模式不看此表。  
**是否开启 GitHub 同步** = 本机是否存在有效 `Entitlements`（已激活）。

## 8. 「API」在现行阶段的对应关系

无服务端。用静态文件代替：

| 原 API 意图 | 现行做法 |
|-------------|----------|
| `GET /config/stages` | `fetch('data/stages.json')` |
| `POST /license/redeem` | 读 `codes.json` + 写 localStorage；激活后允许同步 |
| `GET/PUT progress` | 未激活：仅 localStorage；已激活：localStorage + 中转写入 GitHub |
| `CRUD /admin/*` | 本地改 JSON → git commit / push |

## 9. MVP 开发顺序（建议）

1. 仓库 + GitHub Pages 能打开空白壳页面  
2. 放入 `data/stages.json` + 木墙 `a` 关 → 打磨后复制 a–z  
3. 世界地图（字母可进，其余锁）  
4. 本机进度（未激活路径）+ `EntitlementGate` / 输码  
5. 激活后静默同步（先留接口；再补免费 Worker 写 `data/progress/`）  
6. `APP_EDITION` owner / retail  
7. （更后）支付发码、硬校验；同步中转也可改挂腾讯云  

---

## 10. 以后迁腾讯云时（预留，不实施）

前端仍可留在 GitHub Pages；仅把「校验码 / 进度 / 改价」换成云函数 + PostgreSQL。  
现行 JSON 字段尽量与说明书中的 `StageConfig` / `ActivationCode` 对齐，减少迁移成本。
